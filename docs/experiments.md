# 실험 기록과 남은 검증

추천 규칙을 어떤 순서로, 어떤 근거로 바꿨는지와 앞으로 할 검증을 정리합니다. 규칙과 지표의 정의는 [recommendation.md](recommendation.md)에 있습니다.

## 데이터

| 데이터 | 쓰는 곳 | 비고 |
|---|---|---|
| 개발 앨범 2개 (경주 522장, UNIST 173장) | 규칙 설계, 파라미터 조정 | 주인이 중요 장면 10개와 직접 고른 10장을 표시. 개발 중 계속 들여다본 앨범이라 **최종 성능 근거로 쓰지 않습니다** |
| Photo Triage | 대표 컷 고르기 외부 검증, 순위 모델 학습 | 전체는 15,545장, 묶음 5,953개. 이 중 사람 판단이 공개된 `train_val`만 썼습니다: 사진 12,522장, 쌍 12,558개(train 12,075 + val 483). 라벨이 없는 test는 쓰지 않았습니다. 사람 선호가 정확히 반반(pref=0.5)인 쌍은 정답이 없어 학습과 평가에서 뺍니다(공식 val 483 → 482, 떼어 둔 시험 묶음 1,796 → 1,785) |
| 평가 앨범 (예정) | 최종 검증 | 개발에 쓰지 않은 앨범. 파라미터를 고정한 뒤 정답을 받습니다. 가능하면 서로 다른 주인과 여행에서 받고, 결과에 주인 수와 앨범 수를 함께 적습니다 |

## 버전별 변화

| 버전 | 바꾼 것 | 바꾼 이유 |
|---|---|---|
| r1 | 시간 구간 + CLIP 유사도 0.92로 연사 묶기, 묶음 크기와 MMR로 10장 고르기, 날짜별 자리 배분 | 기준값 0.92는 개발 앨범(100장)에서 유사도 0.84~0.96인 후보 쌍 81개를 모델·평가 담당이 '연사 / 다른 장면'으로 표시해 정했습니다(`pair_check.py`). 0.90과 0.92에서 묶음 결과도 비교했습니다 |
| r2 | CLIP 문장 비교로 만든 **내용 점수** 추가 | 도로, 문서, 스크린샷처럼 보여줄 이유가 없는 사진이 초안에 들어왔습니다 |
| r3 | **방향별 선명도**, 대표 컷을 가장 선명한 컷으로, 관련도에 화질 점수 추가 | 연사 중 흔들린 컷이 대표로 뽑히는 경우가 있었습니다 |
| r4 | **LAION 미적 점수** 추가, 대표 컷을 **Photo Triage로 학습한 순위 모델**로 | 공개 연구의 사람 평가를 반영하고, 대표 컷 규칙을 외부 데이터로 검증하기 위해서입니다. 두 가지를 함께 바꿨으므로, r3 대비 변화를 둘 중 하나의 효과로 나눠 말할 수 없습니다 |

## 실험

### 1. 선명도 측정 방식 (r3)

- **문제:** 기존 라플라시안 분산은 네 방향을 합쳐 재기 때문에, 한 방향으로만 흔들린 사진은 다른 방향의 디테일이 남아 값이 크게 떨어지지 않습니다.
- **방법:** 가로, 세로, 두 대각선 방향 2차 미분의 분산을 각각 구해 가장 작은 값을 씁니다.
- **검증 조건:** 개발 앨범 두 개의 사진 695장(긴 변 192px 축소본)에 인공 블러를 넣고, 원본 전체와 블러 사진 전체를 각 측정값으로 가르는 AUC를 냈습니다. 모션 블러는 n픽셀 평균(직선), 45도는 회전 후 블러를 넣고 되돌린 것입니다.

| 측정 | 가로 3px | 가로 5px | 세로 5px | 45도 5px | 가우시안 σ=0.8 |
|---|---|---|---|---|---|
| 라플라시안 분산 | 0.937 | 0.974 | 0.984 | 0.877 | **0.994** |
| 방향별 최솟값 | **0.987** | **0.997** | **0.995** | **0.925** | 0.988 |

- **해석:** 직선 손떨림은 방향별 측정이 더 잘 가려내고, 초점이 전체적으로 흐린 경우(가우시안)는 비슷하거나 라플라시안이 약간 낫습니다. 이 결과는 방향별 측정을 도입한 근거입니다. 실제 사진에서 흔들린 대표 컷이 줄었는지는 초안 평가의 '흔들림·흐림' 표시로 따로 확인합니다.
- **기록 정정 (2026-11-27):** 이전 기록의 "개발 앨범 사진에서 0.90 → 0.99"는 개발 앨범이 아니라 공개 예제 이미지 106장(512px, 9px 블러)에서 낸 값이었습니다. 개발 앨범 사진으로 다시 재서 위 표로 바꿨습니다.
- **함께 확인한 것:** 앨범 전체에서 선명도가 가장 낮은 사진은 흔들린 사진보다 흰 벽, 하늘, 얼굴 클로즈업이 많았습니다. 그래서 선명도를 절대 기준값으로 거르지 않고, 같은 묶음 안 비교와 앨범 안 백분위로만 씁니다.

### 2. 개발 앨범 비교 (r2 → r4)

값은 경주 / UNIST. 장면 적중과 같은 순간은 10개 중 개수, 백분위는 앨범 안 평균(0~100)입니다.

| 버전 | 장면 적중 | 같은 순간 | 선명도 백분위 | 미적 백분위 |
|---|---|---|---|---|
| r2 | 1 / 4 | 6 / 5 | 58 / 46 | – |
| r3 | 0 / 3 | 4 / 5 | 84 / 85 | 59 / 54 |
| r4 | 1 / 3 | 6 / 3 | 67 / 72 | 86 / 81 |
| 균등 추출 (기준선) | 0 / 0 | 4 / 0 | 42 / 53* | 44 / 45 |

\* 균등 추출 행은 이번에 같은 K=10으로 채웠습니다. 원본이 이 PC에 없어 선명도 백분위만 192px 축소본으로 계산했습니다(r2~r4 행은 512px 축소본). 같은 192px 조건으로 다시 계산한 r4는 장면 적중 1 / 3, 같은 순간 5 / 3, 선명도 백분위 76 / 78입니다.

- **같은 순간:** 합계는 r2 11, r3 9, r4 9로, r3에서 줄어든 뒤 r4에서 늘지 않았습니다(경주는 4→6, UNIST는 5→3).
- **장면 적중:** 합계는 r2 5, r3 3, r4 4입니다.
- **선명도·미적 백분위:** 그 점수를 선택에 쓰기 시작한 버전에서 오르는 것은 예상된 결과입니다. 규칙이 의도대로 작동한다는 확인일 뿐, 주인에게 더 좋은 사진이었는지는 초안 평가의 수용률로 판단합니다.
- **균등 추출과 비교:** 개발 앨범에서는 r4가 장면 적중(4 대 0)과 같은 순간(9 대 4) 모두 높았습니다. 다만 이 앨범들은 규칙을 만들며 계속 본 앨범이라 판정에는 쓰지 않습니다.
- 앨범이 2개, 장면이 10개씩이라 1~2개 차이는 우연일 수 있습니다. 이 표는 방향을 정하는 데만 썼습니다.

### 3. 주인이 고른 사진을 각 점수가 얼마나 가려내나

주인이 고른 10장과 나머지 사진을 점수 하나로 구별하는 AUC입니다(0.5는 무작위).

| 점수 | 경주 | UNIST |
|---|---|---|
| 미적 점수 (LAION) | 0.56 | 0.68 |
| 내용 점수 | 0.51 | 0.71 |
| 선명도 | 0.47 | 0.50 |

두 개발 앨범에서 선명도 하나로는 주인이 최종으로 고른 10장을 가려내지 못했습니다. 다만 고르지 않은 사진 중에도 10장 제한 때문에 빠진 좋은 사진과 거의 같은 컷이 섞여 있어, 이 값이 "사진이 좋은가"를 재는 것은 아닙니다. 이 결과에 따라 선명도는 같은 장면 안에서 컷을 고를 때 주로 쓰고, 장면을 고를 때는 내용 점수와 미적 점수의 비중을 함께 둡니다.

### 4. 앨범 범위

초안이 앨범 전체를 얼마나 덮는지 쟀습니다. 앨범 사진마다 가장 비슷한 초안 사진과의 CLIP 유사도를 구해, **사진 평균**과 **시간 구간 평균**(구간마다 평균을 낸 뒤 다시 평균, 많이 찍은 구간의 영향을 줄임) 두 가지로 냅니다. 최종 규칙 r4, 무작위는 시드 200개 평균입니다.

| 앨범 | K | 사진 평균: r4 / 균등 / 무작위 | 구간 평균: r4 / 균등 / 무작위 |
|---|---|---|---|
| 경주 | 5 | 0.773 / 0.794 / 0.807 | 0.727 / 0.718 / 0.714 |
| 경주 | 10 | 0.826 / 0.851 / 0.839 | 0.771 / 0.753 / 0.747 |
| UNIST | 5 | 0.676 / 0.772 / 0.745 | 0.677 / 0.772 / 0.747 |
| UNIST | 10 | 0.745 / 0.781 / 0.779 | 0.746 / 0.788 / 0.779 |

- 사진 평균으로는 두 앨범 모두 r4가 균등 추출보다 낮습니다. 구간 평균으로는 경주에서 r4가 높고 UNIST에서 낮습니다.
- 어느 쪽으로 재느냐에 따라 결과가 달라서, 원인(예: 덜 찍은 구간이 빠지는지, 많이 찍은 구간을 덜 담는지)을 이 값만으로 판별할 수는 없습니다.
- 자동 초안이 앨범 전체를 고르게 담지 못하는 경우가 있다는 점은 분명하고, 서비스가 초안에 빠진 묶음만 모아 보여주는 **빠진 장면 복구** 화면을 두는 근거입니다.
- 이전 기록의 0.664 / 0.772는 r3, UNIST, K=5, 사진 평균 조건의 값이었습니다.

### 5. 외부 검증: Photo Triage (r4)

- **과제:** 비슷한 사진 묶음에서 여러 사람이 더 좋아한 사진 맞히기. 우리 추천의 "묶음 안 대표 컷 고르기"와 같은 형태의 과제입니다. 정답은 앨범 주인 한 사람이 아니라 여러 평가자의 선호입니다.
- **방법:** 선명도, 미적 점수, 내용 점수를 각각 기준으로 써 보고, 쌍 비교 로지스틱 회귀 3가지(특징 3개 / 문장 15개 / CLIP 512차원 포함)를 학습했습니다. CLIP은 고정합니다.
- **나누기:** train 묶음의 15%를 시험용으로 떼어 두고(묶음 단위), 공식 val에서도 따로 쟀습니다. 규제 세기는 남은 train 안에서 다시 나눈 묶음으로 골랐습니다.
- **채택 기준(실행 전에 정함):** 두 분할 모두에서 선명도보다 쌍 정확도가 3%p 이상 높고, 1등 정확도도 오를 것.

| 방식 | 시험 묶음 쌍 / 1등 | 공식 val 쌍 / 1등 |
|---|---|---|
| 무작위 | 0.488 / 0.414 | 0.525 / 0.446 |
| 선명도 (r3 규칙) | 0.617 / 0.554 | 0.587 / 0.482 |
| 미적 점수 | 0.589 / 0.522 | 0.616 / 0.508 |
| 내용 점수 | 0.572 / 0.487 | 0.591 / 0.472 |
| 학습: 선명도+미적+내용 | 0.635 / 0.548 | 0.620 / 0.528 |
| 학습: 선명도+미적+문장 15개 | 0.640 / 0.542 | 0.627 / 0.513 |
| **학습: 선명도+미적+내용+CLIP 512** | **0.655 / 0.586** | **0.705 / 0.651** |

- 두 분할에서 사전에 정한 채택 기준을 만족한 후보는 CLIP 512 모델이었고, 이 모델을 대표 컷 규칙으로 썼습니다. 시험 묶음에서 선명도 대비 쌍 +3.8%p, 1등 +3.2%p입니다.
- 두 분할 모두 세 후보 중 하나를 고르는 데 썼으므로, 둘 다 모델 선택에 관여한 값입니다. 모델 선택에 쓰지 않은 독립 시험 결과는 없습니다.
- 시험 묶음은 쌍 1,785개(묶음 684개), 공식 val은 쌍 482개(묶음 195개)입니다. 반반인 쌍을 뺀 수입니다. 같은 묶음의 쌍은 사진을 공유해 서로 독립이 아니므로, 단순 쌍 수로 신뢰구간을 내지 않고 관측값만 보고합니다. 개선 폭의 불확실성은 묶음 단위 부트스트랩이 필요하며, 아직 하지 않았습니다.
- 선명도 하나만으로도 무작위보다 확실히 나아서, r3의 "대표 컷은 선명한 컷" 규칙이 여러 사람의 선호와 맞는 방향이었음을 외부 데이터로 확인했습니다.
- 전체 표는 [recommendation.md](recommendation.md#외부-검증-photo-triage)와 [results/triage_result.csv](results/triage_result.csv)에 있습니다.
- **표준화 통계 재검증 (2026-11-27):** 내용 점수·문장 점수의 표준화 통계를 학습 묶음 사진(10,226장)만으로 다시 내고, 같은 분할·시드에서 예전 방식(`train_val` 사진 전체 12,522장, 시험 묶음과 공식 val 사진 포함)과 함께 다시 학습·평가했습니다. 위 표는 학습 묶음만으로 낸 값입니다.
  - 예전 방식 표는 이전 결과와 소수 셋째 자리까지 같아, 코드를 바꾼 뒤에도 재현됨을 확인했습니다.
  - 두 방식의 차이는 내용 점수가 들어간 값에서만 0.001~0.005였습니다(예: 내용 점수 단독 공식 val 쌍 0.593 → 0.591, 작은 학습 모델 시험 묶음 1등 0.547 → 0.548). CLIP 512 모델과 문장 15개 모델의 값은 같았습니다. 문장 15개 모델은 특징마다 차이의 표준편차로 다시 나누므로 이론상으로도 영향을 받지 않습니다.
  - 미리 정한 규칙에 따라 CLIP 512 모델이 채택 기준을 그대로 통과해, 학습 묶음만으로 표준화한 모델로 `model/triage_ranker.npz`를 바꿨습니다. 가중치 차이는 코사인 유사도 0.99999999 수준이고, 개발 앨범에서 대표 컷이 바뀐 묶음은 경주 0/88, UNIST 0/13, 초안도 같았습니다.
  - 이에 따라 `rule_version`이 `r4/clip_vision_model_quantized/a4a8ad41`에서 `r4/clip_vision_model_quantized/f183ab07`로 바뀌었습니다. 두 표는 [results/triage_result.csv](results/triage_result.csv)의 `stats` 열(`train` / `all`)에 모두 있습니다.
- 개발 앨범(경주)에 적용하면 2장 이상 묶음 88개 중 43개의 대표 컷이 바뀌었습니다. 직접 확인해 보니 대부분 같은 자세의 거의 같은 사진 사이의 교체였고, 흔들린 컷을 고른 경우는 없었습니다. 이것은 바뀐 빈도이고, 주인이 바뀐 쪽을 더 좋아했는지는 재지 않았습니다.

## 남은 검증

파라미터와 모델은 지금 `model/params.json`, `model/triage_ranker.npz`(`rule_version` `r4/clip_vision_model_quantized/f183ab07`, 2026-11-27 표준화 재검증 반영)로 고정하고, 아래 결과를 본 뒤에는 바꾸지 않습니다.

1. **평가 앨범으로 최종 비교**
   - 개발에 쓰지 않은 여행 앨범 2개 이상을 정합니다.
   - 앨범 주인이 추천을 보기 전에 정답 페이지(`labeler.py`, 노트북 3번)에서 중요 장면과 10장을 표시합니다.
   - 비교 평가(`evaluate.py`, 노트북 5번)로 제안 방식, 시간만 쓴 묶기, 균등 추출, 무작위를 비교합니다. 시간만 쓴 묶기는 묶기만 다르고, 대표 컷·날짜 배분·선택 규칙은 제안 방식과 같습니다.
2. **초안 평가와 장면 판정**
   - 같은 평가 앨범에서 초안 평가(`draft_review.py --owner`, 노트북 6번)를 합니다. 개발 앨범의 결과는 따로 표로 내고 판정에는 쓰지 않습니다.
   - 세 방식(제안, 관련도의 화질·미적 점수를 끈 방식, 균등 추출)의 초안 사진을 합쳐 섞고, 어느 방식이 골랐는지 숨깁니다. 같은 사진은 한 번만 묻습니다.
   - 주인은 사진마다 세 가지를 따로 답합니다. 수용 여부와 흐림 여부는 나중에 분리할 수 없으므로 처음부터 나눠 받습니다.
     - "여행에 함께 가지 않은 친구에게 보여줄 최종 10장에 이 사진을 그대로 넣어도 되나요?" → 예 / 아니오 (수용률)
     - "이 사진에서 흔들림이나 흐림이 눈에 띄나요?" → 예 / 아니오 (흐림 수)
     - "미리 정한 중요 장면 중 이 사진으로 대신 보여줄 수 있는 장면은 무엇인가요?" → 장면 번호 하나 또는 해당 없음. 선택지에는 장면 번호, 짧은 이름(촬영 시각), 참고 사진을 함께 보여줍니다.
   - **장면의 단위:** 정답 페이지의 기본 표시 방식에서는 ★ 하나마다 장면이 하나 만들어지므로, 중요 장면과 주인이 고른 사진이 일대일입니다. 주인이 고급 화면(`#advanced`)으로 여러 ★를 한 장면에 묶었다면 그 장면을 하나로 셉니다. 페이지를 만들 때 일대일인지 출력합니다.
   - **인정 장면:** 방식마다 그 초안이 담은 서로 다른 장면 수입니다. 한 사진은 한 장면만 대신하고, 같은 장면을 여러 장 담아도 한 번만 셉니다.
   - **자동 대응과의 대조:** 페이지를 만들 때 사진마다 '같은 순간' 규칙(같은 사진, 또는 10분 이내이면서 CLIP 유사도 0.80 이상)으로 대응되는 장면을 미리 계산해 둡니다(화면에는 보이지 않음). 채점할 때 사진 단위로 **같은 장면 / 자동만 인정 / 주인만 인정 / 서로 다른 장면 / 둘 다 없음**을 셉니다. 개수가 같아도 서로 다른 장면일 수 있으므로, "자동 지표가 주인 판단과 맞았다"는 같은 장면 비율로만 말합니다.
3. **기여도 비교 (ablation)**
   - 평가 앨범에서 미적 점수, 화질 점수, 내용 점수, 학습 순위 모델을 하나씩 끄고 지표 변화를 봅니다. 파라미터는 고정한 채로 비교만 합니다.
4. **편집 경험** (두 세션으로 나눔)
   - **시간 비교 (편집용 앨범):** 정답 표시를 하지 않은 참가자 본인의 앨범으로, 직접 선택과 추천 편집을 참가자마다 순서를 바꿔 수행합니다. 미리 10장을 골라 본 기억이 시간에 섞이지 않게 하기 위해서입니다. 두 조건의 앨범은 사진 수와 연사 비율을 비슷하게 맞춥니다. 불러오기부터 확정까지의 총시간, 화면이 준비된 뒤 실제로 고른 시간, 만족도(1~5점)를 기록합니다.
   - **복구한 장면 (평가 앨범):** 중요 장면을 미리 표시한 평가 앨범에서, 초안 평가를 마친 뒤 주인이 추천 초안을 앱에서 한 번 편집합니다. 최종본에 새로 담은 중요 장면 수(초안에 없다가 들어옴)와 편집 중 빠진 중요 장면 수(초안에 있다가 빠짐)를 셉니다. 같은 장면 안에서 다른 컷으로 바꾼 것은 대표 컷 교체로 따로 셉니다. 이 세션은 정답을 이미 표시한 앨범이라 시간 비교에서 뺍니다.
   - 시간 비교는 "서비스 전체가 직접 선택보다 시간을 줄였는가"를 보여줍니다. 추천 규칙 자체의 효과(예: 균등 추출 초안으로 시작하는 조건과 비교)는 이번 실험 범위 밖입니다.
5. **서비스 연동 확인**
   - 실제 앨범으로 앱에서 불러오기부터 확정까지 한 번에 실행해, 처리 시간과 오류가 없는지 확인합니다.

결과를 본 뒤 유리한 지표를 고르지 않도록, 평가 앨범의 정답을 받기 전에 아래 규칙을 정해 둡니다. 결과가 규칙에 맞지 않아도 규칙은 바꾸지 않고, 그대로 보고합니다.

**변경 기록:** 모두 평가 앨범의 정답을 받기 전에 고쳤습니다.

  - 자동 지표 '같은 순간'을 사람 판단으로 검증하도록 '인정 장면'을 추가했습니다.

  - 흐림 수는 낮을수록 좋은 지표라 판정 방향을 따로 정했습니다(아래).
  - Photo Triage 표준화 통계 재검증과, 그 결과에 따른 순위 모델 처리 방법을 미리 정했습니다(아래).

**지표**

- **주 지표:** 같은 순간 (`evaluate.py`, K=10). 주인이 '대신 써도 되는 컷'을 다 표시하지 않아도 같은 순간을 다른 컷으로 담았으면 인정하므로, 정답 표시가 불완전해도 가장 덜 흔들리는 자동 지표입니다. 처음 설계에서는 장면 적중과 일치한 컷을 지표로 정했는데, 개발 앨범에서 주인이 대체 컷을 빠짐없이 표시하기 어려워 같은 순간을 주 지표로 바꿨고, 두 지표는 보조로 계속 냅니다.
- **사람 판단 검증:** 인정 장면 (`draft_review.py --owner`). 제안 방식과 균등 추출에서 같은 순간과 함께 보고합니다. 두 결과의 방향이 다르면 "자동 지표와 주인 판단이 엇갈렸다"고 그대로 씁니다.
- **보조 지표:** 장면 적중, 일치한 컷, 선명도 백분위.
- **초안 평가의 주 지표:** 수용률(초안 K장 중 '건질 사진' 비율).
- **주 비교:** 제안 방식(`time_clip`) 대 균등 추출(`uniform`). 시간만 쓴 묶기(`time`)와 무작위(시드 200개 평균)는 참고로 함께 냅니다. 무작위 시드 200개는 기준선 평균을 안정시킬 뿐, 앨범과 주인의 표본 수는 그대로입니다.

**판정 (각 지표에 똑같이 적용, 새 평가 앨범만 사용)**

| 앨범별 관찰 | 발표할 결론 |
|---|---|
| 모든 앨범에서 제안 방식이 같거나 높고, 한 곳 이상에서 높음 | 평가한 앨범에서 제안 방식이 일관되게 같거나 높았다 |
| 모든 앨범에서 제안 방식이 같거나 낮고, 한 곳 이상에서 낮음 | 평가한 앨범에서 균등 추출이 일관되게 같거나 높았다 |
| 제안 방식이 높은 앨범과 낮은 앨범이 모두 있음 | 앨범별 방향이 엇갈렸다. 앨범별 차이와 합계를 함께 제시한다 |
| 모든 앨범에서 같음 | 평가한 앨범에서 관측값이 같았다 |

- 앨범이 2~3개라 통계적 유의성은 주장하지 않고, 앨범별 값과 주인 수·앨범 수를 모두 공개합니다.
- **화질·미적 점수의 효과 (흐림 수, 낮을수록 좋음):** 앨범마다 `no_quality`의 흐림 수 − 제안 방식의 흐림 수를 냅니다. 이 차이가 모든 앨범에서 0 이상이고 한 곳 이상에서 양수이면 "제안 방식 초안에 흐린 컷이 일관되게 같거나 적었다"(예: 3장 대 1장이면 "2장 적었다"), 모든 앨범에서 0 이하이고 한 곳 이상에서 음수이면 반대로, 엇갈리면 "엇갈렸다", 모두 0이면 "같았다"고 씁니다. `no_quality`는 관련도에서 화질과 미적 점수를 함께 뺀 조건이고, 대표 컷 순위 모델 안의 선명도는 그대로 남습니다. 따라서 결론은 "두 점수를 관련도에서 함께 뺐을 때의 차이"로 한정하고, 선명도 하나의 효과라고 쓰지 않습니다.
- **인정 장면과 같은 순간의 대조:** 제안 방식과 균등 추출 각각에서 사진 단위 대조 결과(같은 장면 / 자동만 / 주인만 / 서로 다른 장면)를 그대로 보고합니다. 인정 장면과 같은 순간의 판정 방향이 다르면 "자동 지표와 주인 판단이 엇갈렸다"고 씁니다.

**Photo Triage 표준화 통계 재검증 (결과를 보기 전에 정함)**

- 같은 분할(묶음 15%, 시드 0)과 같은 후보 3개로, 학습 묶음 사진만으로 표준화한 결과를 다시 냅니다.
- CLIP 512 모델이 기존 채택 기준(두 분할 모두 선명도 대비 쌍 정확도 +3%p 이상, 1등 정확도 상승)을 **여전히 통과하면**, 새로 저장된 `triage_ranker.npz`로 바꾸고 바뀐 `rule_version`을 이 문서에 기록한 뒤 평가 앨범의 초안을 만듭니다.
- **통과하지 못하면**, 다른 후보가 통과하는지 같은 기준으로 보고, 통과한 후보가 없으면 `rank_model`을 `sharpness`(선명도)로 되돌립니다. 어느 경우든 두 표를 모두 보고합니다.
- 재실행을 마치지 못하면 지금 모델을 그대로 쓰고, "표준화 통계가 정확도와 모델 채택에 미친 영향은 측정하지 않았다"고 씁니다.
- **실행 결과 (2026-11-27):** 첫 번째 경우였습니다. CLIP 512 모델이 기준을 그대로 통과해 모델을 바꾸고 `rule_version` `f183ab07`을 기록했습니다(실험 5).

**기여도 비교**

- 점수를 하나씩 끈 결과는 설명용으로만 보고하고, 이 결과로 추천 규칙을 바꾸지 않습니다.

**규칙을 바꿔야 할 때**

- 평가 중에 버그를 찾으면 고치되, `rule_version`이 바뀌므로 고치기 전과 후의 결과를 모두 보고합니다. 성능을 올리려는 파라미터 조정은 하지 않습니다.

## 알려진 한계

- **평가 규모:** 평가 앨범이 2~3개라, 결과는 효과의 방향을 보여줄 뿐 일반화를 보장하지 않습니다.
- **순위 모델의 도메인 차이:** 순위 모델은 Photo Triage(일상 개인 앨범의 연사, 여러 평가자의 선호)로 학습했습니다. 여행 앨범에서 이 모델이 선명도 규칙보다 주인에게 더 좋은 컷을 고르는지는 따로 재지 않았습니다. 이를 재려면 r3와 r4의 대표 컷이 다른 묶음만 주인에게 좌우를 섞어 보여주고 선호를 받는 실험이 필요합니다. 지금 여행 앨범에서의 근거는 개발 앨범에서 바뀐 대표 컷을 눈으로 확인한 것(흔들린 컷 선택 없음)뿐입니다.
- **Photo Triage 표준화 통계:** 처음 모델은 시험 묶음과 공식 val 사진까지 포함한 통계로 표준화했습니다. 학습 묶음만으로 다시 낸 결과 정확도 차이는 0.001~0.005였고 모델 채택은 바뀌지 않아, 지금 모델은 학습 묶음만으로 표준화한 것으로 바꿨습니다(실험 5).
- **내용 점수의 표준화 기준:** 학습할 때는 Photo Triage 사진 전체 기준, 추천할 때는 앨범 하나 기준으로 표준화합니다. 개발 앨범에서 이 항을 0배~2배로 바꿔도 대표 컷이 바뀐 묶음은 경주 88개 중 2개 이하, UNIST 13개 중 0개라 영향은 작습니다. 나머지 입력(선명도, 미적 점수, CLIP 벡터)은 학습과 추천에서 같은 함수로 계산합니다.
- **같은 순간 채점의 임베딩:** 같은 순간은 추천 모델이 만든 묶음과 상관없이 시간(10분)과 유사도(0.80) 기준으로 채점합니다. 하지만 추천과 같은 CLIP 임베딩으로 유사도를 재므로 제안 방식에 유리할 수 있고, 배경이 비슷한 다른 순간을 같은 순간으로 보거나 같은 순간의 다른 구도를 놓칠 수 있습니다. 이를 확인하려고 초안 평가에서 주인의 장면 판정(인정 장면)을 함께 받습니다.
- **앨범 범위:** 실험 4처럼 측정 방식에 따라 결과가 달라지고, 사진 평균으로는 제안 방식이 균등 추출보다 앨범을 덜 덮습니다. 서비스에서는 빠진 장면 복구 화면으로 보완합니다.
- **선명도 실험 조건:** 실험 1은 192px 축소본과 인공 블러로 낸 값이라, 실제 손떨림이나 원본 해상도에서의 차이는 다를 수 있습니다.
- **작은 앨범:** 사진 1~7장 앨범과 모든 사진이 같은 앨범에서도 오류 없이 초안이 나오는 것을 확인했습니다. 다만 이런 앨범에서는 백분위 점수의 의미가 약합니다.
