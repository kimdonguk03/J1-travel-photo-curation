# 추천 규칙과 평가

`model/` 폴더의 추천 규칙, 파라미터, 평가 도구를 설명합니다. 서버에서 호출하는 방법은 [api.md](api.md)에 있습니다.

## 추천 규칙

사전학습된 CLIP ViT-B/32 이미지 인코더의 가중치를 고정해 씁니다. 모델은 `Xenova/clip-vit-base-patch32`의 `onnx/vision_model_quantized.onnx`이고, 512차원 `image_embeds`를 냅니다. 각 사진의 벡터는 한 번만 계산해 캐시합니다. 내용 점수에 쓰는 문장 벡터는 같은 CLIP의 글 인코더로 미리 계산해 `model/content_prompts.npz`에 저장해 두므로, 실행할 때는 이미지 인코더만 씁니다. 문장을 바꾸려면 `content_prompts.py`를 고친 뒤 다시 실행합니다(`tokenizers` 설치 필요).

| 단계 | 규칙 |
|---|---|
| 입력 | EXIF DateTimeOriginal로 촬영 시각을 읽고, 없으면 미상으로 둡니다. 회전은 한 번만 적용하고, 정방향 512px 축소본에서 선명도와 CLIP 입력을 만듭니다 |
| 선명도 | 흑백 축소본에서 가로·세로·두 대각선 방향 2차 미분의 분산을 각각 구하고 그중 가장 작은 값을 씁니다. 손떨림은 흔들린 방향의 디테일만 지우기 때문에, 네 방향을 합친 라플라시안보다 흔들림을 잘 잡습니다 |
| 시간 구간 | 촬영순으로 직전 컷과 30초, 구간 첫 컷부터 120초 한도를 둡니다. 어느 한도를 넘거나 날짜가 바뀌면(자정 기준) 새 구간입니다. 촬영 시각 미상은 단독 후보입니다 |
| 유사 컷 묶기 | 같은 구간에서 각 묶음의 첫 컷(기준 컷)과만 비교합니다. 유사도 0.92 이상인 묶음 중 가장 높은 곳에 넣고, 없으면 새 묶음을 만듭니다. 동점이면 먼저 만든 묶음입니다 |
| 내용 점수 | 사진의 CLIP 벡터를 문장 15개(`content_prompts.npz`)와 비교하고, 문장마다 앨범 안에서 표준화한 뒤 '보여줄 만한 내용' 9개 평균에서 '빼고 싶은 내용' 6개 평균을 뺍니다. 가중치는 학습하지 않고 모두 같습니다 |
| 대표 컷 | 묶음 안에서 선명도가 큰 순, 같으면 내용 점수가 높은 순, 그다음 촬영순입니다. 같은 묶음은 거의 같은 장면이라, 선명도 차이는 대부분 흔들림이나 초점 차이입니다. `rank_model`을 바꾸면 선명도 대신 Photo Triage 사람 선호 데이터로 학습한 점수로 고릅니다(아래 외부 검증) |
| 화질 점수 | 대표 컷 선명도의 앨범 안 백분위(0~1)입니다 |
| 미적 점수 | [LAION-Aesthetics V1](https://github.com/LAION-AI/aesthetic-predictor)의 ViT-B/32 선형층을 대표 컷의 CLIP 벡터에 씌운 값의 앨범 안 백분위(0~1)입니다. 사람이 매긴 미적 점수로 학습된 공개 모델(MIT)이라, 손으로 쓴 문장 대신 사람 평가를 반영합니다. 추가 추론 없이 벡터 곱 한 번으로 계산합니다 |
| 점수 | `관련도 = 크기 점수, 내용 점수, 화질 점수, 미적 점수의 가중 평균`이고, 비중은 모두 1(각 1/4)입니다. 크기 점수는 `min(사진 수, 5)/5`, 내용 점수는 대표 컷 값을 앨범 안 0~1로 바꾼 값입니다. `MMR = (1-λ) x 관련도 - λ x 중복도`. 중복도는 지금까지 고른 대표 컷과의 최대 코사인 유사도이고, 첫 선택은 0입니다. 동점은 대표 컷의 촬영순입니다 |
| 자리 배분 (묶음 ≥ K) | 아래 두 단계로 K장에서 멈춥니다 |
| 부족분 채우기 (묶음 < K) | 모든 대표 컷을 고른 뒤 묶음별 2위, 3위를 첫 컷 촬영순으로 돌아가며 채웁니다 |

자리 배분은 이렇게 합니다.

1. 날짜마다 MMR 1위 대표 컷을 1장씩 고릅니다. 날짜 수 D가 K보다 많으면 `floor((j+0.5)D/K)`번째 날짜만 씁니다.
2. 남은 자리는 `√사진 수/(배정 수+1)`이 가장 큰 구간의 MMR 1위로 채웁니다. 촬영 시각 미상은 이 단계부터 참여합니다.

K는 min(10, 유효 사진 수)이고, 초안은 서로 다른 K장입니다. 디코딩에 실패한 사진은 초안 후보에서 뺍니다. 실패한 사진의 벡터는 영벡터라 중복도가 0이 되어, 그대로 두면 MMR에서 오히려 유리해지기 때문입니다.

## 파라미터 (`model/params.json`)

| 키 | 기본값 | 의미 |
|---|---|---|
| `seg_gap_sec` | 30 | 직전 컷과의 간격 한도(초) |
| `seg_span_sec` | 120 | 구간 첫 컷과의 간격 한도(초) |
| `clip_sim` | 0.92 | 같은 묶음으로 보는 기준 컷과의 유사도 |
| `lambda` | 0.5 | MMR의 중복도 가중치 |
| `size_cap` | 5 | 크기 점수의 상한 사진 수 |
| `size_weight` | 1 | 관련도에서 크기 점수의 비중 |
| `content_weight` | 1 | 관련도에서 내용 점수의 비중 (0이면 내용 점수를 쓰지 않음) |
| `quality_weight` | 1 | 관련도에서 화질 점수의 비중 (0이면 선명도는 묶음 안 대표 컷 고르기에만 씀) |
| `aesthetic_weight` | 1 | 관련도에서 미적 점수의 비중 (0이면 쓰지 않음) |
| `rank_model` | `sharpness` | 묶음 안 대표 컷 고르기. `sharpness`(선명도) 또는 `triage_ranker.npz`에 든 학습 모델 `small`(선명도·미적·내용), `prompts`(선명도·미적·문장 15개), `clip`(선명도·미적·내용·CLIP 512) |
| `day_start_hour` | 0 | 날짜 경계 시각 |
| `random_seeds` | 200 | 무작위 기준선을 평균 낼 시드 수 |

파라미터는 개발 앨범에서만 조정하고, 평가 전에 고정합니다. 출력되는 `rule_version`(예: `r4/clip_vision_model_quantized/1a2b3c4d`)은 규칙 코드, 특징 계산, 파라미터, 모델, 내용 점수 문장, 미적 점수 가중치로 만들어지므로 결과가 어떤 조건에서 나왔는지 구분할 수 있습니다.

## 도구

아래 명령은 모두 `model/` 폴더에서 실행합니다. 캐시와 결과는 `model/j1_out/`에 저장되고, 원본 폴더에는 아무것도 쓰지 않습니다.

### 개발 앨범 점검

```powershell
py curation.py "C:\Photos\dev_album"
```

- 모델 로딩, 원본 디코딩, CLIP 추론 시간을 따로 출력합니다.
- `clusters.html`: 시간 구간, 묶음, 대표 컷 순위를 보여줍니다. 유사도가 기준값 근처(0.86~0.96)인 **경계 사례**를 기준 컷과 나란히 보여줘서, 실제 연사가 갈라졌는지와 다른 장면이 합쳐졌는지를 확인할 수 있습니다.
- `compare.html`: 방식별 초안
- `recommend_result.json`: `recommend()` 반환 예시

### 기준값 점검

```powershell
py pair_check.py "C:\Photos\dev_album"
```

`pairs.html`에서 사진 쌍을 직접 표시하면, 현재 기준값이 두 경우를 얼마나 잘 가르는지 계산합니다.
- **연사:** 한 장만 남겨도 되는 같은 컷 (같은 묶음이어야 함)
- **다른 장면:** 같은 장소라도 둘 다 남겨야 하는 사진 (따로 남아야 함)

화면은 이렇게 구성됩니다.
- **쌍 고르기:** 10분 이내에 연달아 찍은 사진 쌍 중 유사도가 0.84~0.96인 쌍만 후보로 나옵니다. 이 구간 밖은 대부분 판단이 분명해서 빼고, 표시가 10분 안팎으로 끝나게 했습니다. 구간은 `--low`, `--high`로 바꿀 수 있습니다. 그 밖의 쌍은 사진 두 장을 눌러 직접 추가합니다.
- **표시 중에는 유사도를 숨깁니다.** 판단이 숫자에 끌리지 않게 하기 위해서입니다.
- **결과 표:**
  - 표시별 유사도 분포
  - 현재 기준값에서의 정답률: 두 사진의 유사도로 본 결과와 실제 묶기 결과를 함께 보여줍니다
  - 기준값 0.80~0.98별 정답률
  - 틀린 쌍 목록
- **CSV 내보내기:** 표시 결과를 CSV로 저장합니다.

### 정답 수집

```powershell
py labeler.py "C:\Photos\jeju_trip" --album-id jeju
```

앨범 주인이 `label_*.html`에서 직접 표시합니다. 이 페이지에는 추천 결과가 없으며, 정답은 추천을 보여주기 전에 받습니다. 화면에는 ★ 버튼과 [저장]만 있습니다.
- **owner_pick:** 친구에게 보여줄 10장에 ★를 누릅니다. ★는 10장까지만 누를 수 있고, 사진을 눌러서는 ★가 되지 않습니다.
- **scene_id:** ★를 누르면 그 사진의 장면이 화면에 보이지 않게 자동으로 만들어집니다.
- **2단계 (선택):** 10장을 다 고르면 [2단계] 버튼이 생깁니다. 고른 사진을 하나씩 보여주면서 앞뒤 사진(같은 날, 30분 이내, 앞뒤 12장)을 함께 보여주고, '그 사진 대신 보여줘도 괜찮은 사진'을 고르게 합니다. 고른 사진은 그 장면의 인정 컷이 되어, 추천이 같은 장면의 다른 컷을 골라도 장면 적중으로 인정됩니다. 직접 장면을 편집하려면 페이지 주소 끝에 `#advanced`를 붙여 엽니다.

- **거의 같은 연사는 접어서 보여줍니다:** 10초 이내에 찍었고 유사도가 0.96 이상인 사진은 한 장(가장 선명한 컷)으로 접혀 보이고, 접힌 사진에 ★를 누르면 묶음 전체가 인정 컷이 됩니다. 추천 기준값(0.92)보다 엄격하게 잡아 사람이 봐도 같은 사진만 묶이게 했고, `--dup-sim`, `--dup-gap`으로 조정하거나 `--embedder none`으로 끌 수 있습니다. 평가 결과를 보고할 때는 이 처리를 함께 밝힙니다.

표시는 10분 안팎이면 끝납니다.

저장하면 `owner_*.csv`가 나옵니다.

| 열 | 의미 |
|---|---|
| `album_id` | 평가 앨범과 정답을 연결하는 식별자 |
| `scene_id` | 중요 장면 (예: `S01_해변 단체사진`). 같은 장면을 대신할 수 있는 컷은 같은 값 |
| `relpath` | 앨범 루트 기준 상대 경로 (구분자 `/`) |
| `owner_pick` | 주인이 직접 고른 컷이면 1 |

### 평가

```powershell
py evaluate.py "C:\Photos\jeju_trip" owner_jeju.csv "C:\Photos\busan_trip" owner_busan.csv --params params.json
```

| 방식 | 내용 |
|---|---|
| `uniform` | 촬영 순번 균등 추출 (기준선) |
| `time` | 시간 구간을 그대로 묶음으로 쓰고, 이후 선택 규칙은 제안 방식과 같음 |
| `time_clip` | 제안 방식 |
| `random` | 참고용 하한선 (시드 평균) |

| 지표 | 정의 |
|---|---|
| 장면 적중 | 초안 K장이 인정 컷을 하나 이상 담은 중요 장면 수 / 중요 장면 수 |
| 같은 순간 | owner_pick=1인 사진 중, 초안에 같은 사진이 있거나 10분 안에 찍은 유사도 0.80 이상 사진이 있는 수 / owner_pick 수. 주인이 '대신 써도 되는 컷'을 모두 표시하지 않아도, 같은 순간을 다른 컷으로 담았으면 인정합니다. 기준(10분, 0.80)은 새 평가 앨범을 보기 전에 정했습니다 |
| 일치한 컷 | 초안 K장 중 owner_pick=1인 사진과 같은 사진 수 / owner_pick 수 |
| 선명도 백분위 | 초안 사진 선명도의 앨범 안 평균 백분위 (0~100, 높을수록 선명). 정답 없이 계산하는 객관 지표입니다 |

앨범별 표, 방식별로 놓친 장면, 여러 앨범의 평균, CSV를 출력합니다.

### 초안 평가 (수용률 · 흔들림)

```powershell
py draft_review.py "C:\Photos\jeju_trip" --album-id jeju
py draft_review.py --score review_jeju.csv review_busan.csv
```

정답(owner.csv)을 받은 뒤, 앨범 주인이 초안 사진을 직접 평가합니다. 이 페이지는 추천 결과를 보여주므로 정답을 받기 전에는 쓰지 않습니다.
- **보여주는 사진:** 제안 방식(`proposal`), 화질·미적 점수를 끈 방식(`no_quality`), 균등 추출(`uniform`)의 초안을 합쳐 무작위 순서로 섞습니다. 어느 방식이 고른 사진인지는 표시하지 않습니다.
- **표시:** 사진마다 '건질 사진', '흔들림·흐림', '별로' 중 하나를 누르고 [저장]으로 `review_*.csv`를 받습니다.
- **채점:** 방식별로 초안 K장 중 '건질 사진' 비율(수용률)과 '흔들림·흐림' 수를 냅니다. 흔들림 수는 사람이 판단한 화질 지표라, 선명도 점수가 실제로 흔들린 사진을 거르는지 확인하는 데 씁니다.

### 외부 검증: Photo Triage

```powershell
py triage_eval.py C:\data	riage --out triage_result.csv --save-ranker triage_ranker.npz
```

연사 중 한 장 고르기를 [Princeton/Adobe Photo Triage](https://pixl.cs.princeton.edu/pubs/Chang_2016_ATF/index.php)(Chang et al., SIGGRAPH 2016)의 사람 선호 데이터로 검증합니다. 개인 앨범의 비슷한 사진 묶음 안에서 사람들이 두 사진 중 어느 쪽을 더 좋아했는지 모은 데이터이고, 라벨이 공개된 `train_val`만 씁니다. 원래 사이트가 닫혀 Kaggle 복사본(`ericwolter/triage`)을 쓰며, 노트북 7번 섹션이 받기부터 실행까지 합니다.

- **비교:** 선명도(지금 대표 컷 규칙), 미적 점수, 내용 점수, 그리고 이 데이터로 학습한 쌍 비교 로지스틱 회귀(특징 3개 / 문장 15개 / CLIP 512차원).
- **지표:** 쌍 정확도(사람 다수가 고른 쪽을 맞힌 비율, 70% 이상 합의한 쌍 따로), 1등 정확도(묶음마다 가장 높은 점수의 사진이 사람 순위 1등인 비율).
- **나누기:** train 묶음의 15%를 시험용으로 떼어 두고 학습에는 쓰지 않습니다. 규제 세기는 남은 train 안에서 다시 나눈 묶음으로 고릅니다. 공식 val에서도 따로 잽니다.
- **라이선스:** 이미지는 연구용·비상업 라이선스입니다. 이 프로젝트는 연구 대회 출품작이라 연구 목적 사용에 해당하며, 논문을 인용하고 이미지는 저장소에 올리지 않습니다.
- **추천에 쓰기:** `--save-ranker`로 저장한 파일을 `model/triage_ranker.npz`로 두고 `params.json`의 `rank_model`을 바꿉니다. 시험 묶음과 공식 val 모두에서 선명도보다 확실히 나은 모델만 씁니다(쌍 정확도 3%p 이상, 1등 정확도도 함께 오를 때). 어느 모델을 썼는지는 `rule_version`에 남습니다.

## 알려진 한계

- **압축에 따른 흔들림:** 기준값 0.92 근처의 판정은 압축 방식에 따라 바뀔 수 있습니다. 같은 사진을 HEIC로 다시 저장하면 유사도가 최대 0.03 정도 달라졌습니다. 캐시는 이 영향을 줄이려고 무손실 PNG로 저장합니다.
- **장면에 따라 선명도 값이 다릅니다:** 흰 벽, 하늘이 넓은 풍경, 얼굴 클로즈업은 흔들리지 않아도 선명도 값이 낮게 나옵니다. 그래서 선명도는 같은 묶음 안에서 비교할 때 가장 믿을 만하고, 묶음끼리 비교할 때는 절대 기준값으로 거르지 않고 백분위 점수로 관련도에 1/3만 반영합니다. 실제로 흔들린 사진을 얼마나 거르는지는 초안 평가의 '흔들림·흐림' 표시로 확인합니다.
- **휴대폰 크기 HEIC는 디코딩이 느립니다:** 1장에 약 1초가 걸립니다. 4개 스레드로 병렬 처리하고, 한 번 디코딩한 결과는 캐시합니다.
